LOCAL INTEGRATION EXAMPLE

One login. Your own workspace.

This separate example uses SwopMobile’s existing API adapter. The server owns the permissions; hiding a button does not protect data.

Protected workspace

What happens behind this screen?

Registration hashes your password. Login returns short-lived access and rotating refresh tokens. Protected API requests validate the signature and active session, then use your server-side user ID to select your records. Logout revokes the session.

Tokens live in session storage in this existing demo client. Script injection can expose them. This is a local teaching example, not a claim of production readiness.
